# ربط GitHub مع GreasyFork

الهدف: يكون GitHub هو المصدر الرئيسي، بينما يبقى GreasyFork واجهة التثبيت والتحديث للمستخدمين.

## للسكربتات الموجودة أصلًا على GreasyFork

لا ننشئ صفحة GreasyFork جديدة ولا نغيّر رابط السكربت الحالي.

بعد وجود ملف `.user.js` المستقر على فرع `main`:

1. افتح صفحة السكربت في GreasyFork.
2. افتح صفحة إدارة السكربت.
3. اضبط المزامنة من URL خارجي على رابط **Raw** لملف `.user.js` في فرع `main`.
4. استخدم رابط الفرع `main` وليس رابط Commit ثابتًا.
5. اختبر مزامنة إصدار تجريبي برفع `@version` بصورة صحيحة.

## Webhook

بعد ضبط السكربت للمزامنة من GitHub يمكن إعداد Webhook من إعدادات المستودع لتسريع وصول التحديثات إلى GreasyFork.

يفضل لمشروعنا أن يكون النشر مرتبطًا بالنسخ المستقرة فقط، لذلك لا نربط GreasyFork بفرع `dev`.

## رابط Raw القياسي

الصيغة العامة:

```text
https://raw.githubusercontent.com/M0HM3D85/teacher-userscripts/main/scripts/<script-id>/<script-file>.user.js
```

## قواعد مهمة

- `main` فقط هو مصدر GreasyFork.
- لا تغيّر الكود مباشرة في GreasyFork بعد اكتمال الربط؛ عدّله في GitHub أولًا.
- كل تغيير في ملف منشور يجب أن يصاحبه رفع مناسب لـ `@version`.
- لا تستخدم Loader يخفي الوظيفة الأساسية خارج GreasyFork؛ الملف المتزامن نفسه هو السكربت الكامل.
- لا تربط GreasyFork بفرع تطوير أو Commit مؤقت.

## التحقق بعد النشر

1. افتح صفحة GreasyFork وتأكد أن رقم الإصدار الجديد ظاهر.
2. افتح Tampermonkey وافحص التحديثات.
3. تأكد من أن المستخدم ينتقل للإصدار الجديد دون إعادة تثبيت السكربت.
4. اختبر الصفحة المستهدفة مرة أخيرة بعد التحديث.
